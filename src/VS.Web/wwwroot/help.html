Deployment and Security Guide

This offline guide documents the Windows service, processes, ports, protocols, data locations, deployment checks, known security limitations, and vulnerability-response procedure for VITEC Scoreboard.

Download Word Guide

Secure Deployment Summary

  • Deploy only on a trusted, segmented internal network.
  • Do not expose the webpage/API port directly to the Internet.
  • Restrict the inbound firewall rule to approved management, signage, and EZ TV subnets.
  • Do not install the LocalSystem service on a domain controller.
  • Use unique PostgreSQL credentials and protect the ProgramData settings file.
  • Keep Windows, .NET, CefSharp/Chromium, FFmpeg, PostgreSQL, and NuGet dependencies patched.

Important Current Limitations

  • The web interface currently uses HTTP and has no built-in login or role-based access control.
  • The PostgreSQL application password is stored in the protected local settings file.
  • UDP multicast is not encrypted or authenticated.
  • Production deployments should use signed installers/executables and retained release hashes.

When a Vulnerability Is Reported

  1. Identify: collect the application version, dependency versions, logs, firewall rules, affected host, and indicators.
  2. Contain: restrict network access or isolate the host; preserve logs before changing state.
  3. Assess: determine affected versions, reachability, privilege impact, and credential/data exposure.
  4. Remediate: patch or upgrade, rotate exposed credentials, remove unauthorized changes, and restore from trusted media where necessary.
  5. Validate: rescan and test service, API, database, and video-output functions.
  6. Communicate: notify affected customers with impact, affected versions, mitigations, fixed version, and required actions.
